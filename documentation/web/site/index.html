Your cluster, explained while it runs

A three-node Kubernetes cluster on your laptop, a local test environment that simulates a production cluster: each node is a Docker container here, where production runs machines such as EC2 instances on AWS. It runs a real stock-price service with its database and UI, one Gateway (Envoy) for all incoming traffic, a secret store (Vault), and observability: metrics (Prometheus), alerts (Alertmanager), traces (OpenTelemetry and Tempo) and dashboards (Grafana). Diagrams marked Live are drawn from the running cluster, so they show what is there right now.

Architecture

How it all fits together

Boxes are workloads, grouped and coloured by namespace. Lines are mostly what the cluster itself says connects them: HTTPRoutes, Service addresses in environment variables, Prometheus annotations and RBAC bindings. Arrows point the way the data moves. Moving dashes are real traffic, measured by Prometheus. Select a box to see its live details.

Requests: the data plane

What your browser and the apps send each other. Every request from outside enters through one Envoy proxy. Inside the cluster, pods call Services by DNS name.

Telemetry

What the cluster says about itself. Prometheus pulls metrics from every annotated Service, so the metrics flow to it, and sends firing alerts to Alertmanager. stock-app pushes traces to the OpenTelemetry Collector, which forwards them to Tempo.

Control plane

Who watches the Kubernetes API. Controllers turn objects into running config: Envoy Gateway turns HTTPRoutes into Envoy routes, and this site turns pods into these diagrams.

Make it move. Open traffic-generator, pick Get bars and send 50 requests. Then come back to the diagram above, on its Requests layer: the dashes from Envoy to stock-app speed up and show the request rate, then those from stock-app to TimescaleDB. On the Telemetry layer the same requests leave stock-app as spans.

Get going

Run it

You need:

  • Docker with at least 6 GB of memory: the three nodes use about 3.3 GiB when idle.
  • kind v0.33.x: the script stops if your kind has another version.
  • kubectl 1.36 to 1.38: kubectl supports one minor version either side of the API server.
  • curl, and host ports 80 and 443 free: the script stops if something else listens on them.
  • Go 1.26, Node.js 24 and Python 3.14 only to change the code.

Start from scratch: delete any existing sample-cluster with all its data, then create it with every component. Safe to re-run.

./recreate-cluster.sh

The same, but stock-app generates its prices instead of calling Yahoo Finance: works offline, and it is what CI runs.

STOCK_PROVIDER=synthetic ./recreate-cluster.sh

It builds the four local images, deploys everything and waits until every *.localhost URL answers. Build & ship shows each step. *.localhost resolves to 127.0.0.1 on macOS and most Linux systems, so there is no DNS to set up.

kind binds ports 80 and 443 on every network interface (0.0.0.0), so other devices on your network can reach Vault (token root) and Grafana (admin / admin). On a shared network, add listenAddress: "127.0.0.1" to both port mappings in platform/kind-cluster.yaml.

When it doesn't start

Troubleshooting

Host port 80 or 443 is in use

Find what listens on it with sudo lsof -iTCP:80 -sTCP:LISTEN (or :443), stop it and re-run. kind can only map a free port.

kind has the wrong version, or unknown containerd config version: 4

An older kind builds an older Kubernetes and can't load images into newer nodes. Check kind version and install v0.33.x.

Pods stay Pending or get OOMKilled

Docker has too little memory. Give it at least 6 GB (Docker Desktop: Settings → Resources) and re-run. kubectl describe pod shows Insufficient memory or the kill reason.

stock-app answers 502 for new symbols

Yahoo Finance limits how often you may call it. Use generated prices instead: STOCK_PROVIDER=synthetic ./recreate-cluster.sh.

*.localhost does not resolve

Some Linux setups don't send *.localhost to 127.0.0.1. Browsers do it themselves. For curl, give the name in the Host header: curl -H 'Host: stock.localhost' http://127.0.0.1/health.

Your first hour

Six steps, each with a checkpoint that tells you it worked.

  1. runRun it. Checkpoint: the script ends with ✅ Cluster ready and this site opens at docs.localhost.
  2. lookRead the overview diagram and select a few boxes. Checkpoint: every box has a green dot.
  3. trafficOpen traffic-generator and send 50 requests to stock-app. Checkpoint: the dashes from Envoy to stock-app move, and the pulse tiles rise.
  4. traceChart a new symbol at stock-ui and find its trace. Checkpoint: a waterfall where Yahoo takes most of the time.
  5. breakStop the database. Checkpoint: stock-app's dot turns red, and its EndpointSlice lists the pod with ready=false.
  6. fixScale the database back to 1. Checkpoint: stock-app turns green again without restarting (RESTARTS stays 0).

Words

Glossary

One line each. The link goes to where the site explains it.

CA
Certificate authority: signs certificates. A client trusts a server's certificate if a CA it trusts signed it. Identity
cache-aside
Read the store first. On a miss, fetch from the source and store the result. State
CNI
Container Network Interface: the plugin that gives each pod an IP and routes between nodes. Here it is kindnet. Networking
controller
A program in the cluster that watches objects through the Kubernetes API and changes the real world to match them, such as Envoy Gateway. Networking
DNAT
Destination NAT: kube-proxy's rules rewrite a Service or NodePort address to a pod IP. Networking
EndpointSlice
The list of a Service's pod IPs, each marked ready or not, that kube-proxy and Envoy send traffic to. Networking
exemplar
A metric sample that carries a trace ID, so a latency spike links to one request's trace. Observability
GatewayClass
Names the controller that turns Gateways into a proxy or a cloud load balancer, like a StorageClass for volumes. Networking
inhibition
An Alertmanager rule that hides the alerts another firing alert already explains. Observability
informer
A client-go cache: list each kind of object once, then watch, so reads come from memory. Identity
ndots
A resolver option: names with fewer dots than this try every search domain first. Networking
NodePort
A Service port opened on every node. Here 30080 and 30443 carry host ports 80 and 443 to the Gateway. Networking
OTLP
OpenTelemetry Protocol: how spans travel from stock-app to the Collector and on to Tempo. Observability
PSS, PSA
Pod Security Standards (privileged, baseline, restricted), enforced per namespace by Pod Security Admission. Identity
QoS class
Guaranteed, Burstable or BestEffort, set by requests and limits. It predicts eviction order. Workloads
silence
Mutes matching alerts in Alertmanager until a set time, e.g. during planned work. Observability
xDS
The gRPC APIs over which Envoy Gateway streams routes and endpoints to Envoy. Networking
