Reference · components

Every component, with its live spec sheet

One section per component: what it is for, its facts as the cluster reports them right now, the ideas worth knowing and how to work on it. Each top-level directory of the repository is one component; its Kubernetes manifests live in <component>/k8s/.

apps · the real backend

stock-app

Serves daily stock prices (open, high, low, close, volume) at stock.localhost/api/v1: the instruments it holds, the bars for a date window, and a summary of a window. FastAPI with TimescaleDB, plus POST /secret and GET /secret/{key} backed by Vault.

Contract first

stock-app/openapi.yaml is the API's source of truth: the request and response models are generated from it (tox -e api) and make lint fails if they drift. The running service publishes it at /openapi.yaml, with Swagger UI at /docs, and the e2e tests validate every response against it, /secret included.

Providers

STOCK_PROVIDER=yahoo (the default) calls Yahoo Finance; synthetic generates prices for AAPL, MSFT, NVDA, AMZN and GOOGL without a network, which CI uses because Yahoo rate-limits its runners. Each symbol's prices are a random walk seeded by the symbol, so a date always gets the same bar and nothing expires; they are not real prices. How the cache decides what to fetch: State & storage.

cd stock-app
tox -e tests          # unit tests: no database or network needed
tox -e pre-commit     # lint, import rules, model drift
docker build -t stock-app:dev . && kind load docker-image stock-app:dev --name sample-cluster
kubectl rollout restart deployment stock-app -n apps   # migrations run in its init container
data · stock-app's database

TimescaleDB

PostgreSQL 17 with TimescaleDB, as a StatefulSet with a 2Gi volume, reachable only inside the cluster at timescaledb-service.data:5432 (database stockdata, user stockapp). The data namespace may not attach routes to the Gateway.

  • stock-app's Alembic migrations create the schema, from its init container.
  • The password Secret exists twice, in data and in apps, because Secrets can't cross namespaces.
  • A postgres_exporter sidecar serves pg_* metrics on 9187 (job timescaledb). It logs in as postgres_exporter, a role with only pg_monitor, created on first start by k8s/create-exporter-role.sh. It connects to the postgres database, so its queries don't count as stockdata transactions, the stock-app → TimescaleDB line on the Overview. That line still moves when stock-app is idle (about 0.7 tx/s): its readiness probe checks the database every 5 s, and TimescaleDB's job scheduler commits there too. Per-table statistics (pg_stat_user_tables) only cover the database it connects to, so they aren't collected.
kubectl exec -it timescaledb-0 -n data -c timescaledb -- psql -U stockapp -d stockdata
apps · a frontend

stock-ui

"Stock App", a React (Vite) app at stock-ui.localhost that charts stock-app's daily prices (line or candles, one week to five years). Only the Markets view uses the backend: Portfolio, Watchlist and the account menu are mocked on purpose (src/mocks/demoData.js) and the indicator panels are empty placeholders. Search filters stock-app's instrument list; any other ticker can be typed in full.

cd stock-ui
npm ci
npm run dev      # dev server; VITE_STOCK_API_URL overrides http://stock.localhost
npm test         # Vitest
npm run build    # into dist/, served by non-root nginx on 8080 in the image
apps · a test tool

traffic-generator

A React (Vite) page at traffic-generator.localhost that simulates traffic: pick a stock-app endpoint, send 1 to 100 concurrent requests and see every response. The same traffic shows up in Prometheus, Grafana, Tempo and on this site's architecture diagram.

cd traffic-generator
npm ci && npm run dev    # or npm run build, into dist/
vault · secrets

Vault

HashiCorp Vault in dev mode at vault.localhost, token root: in memory and auto-unsealed, a playground only. Every restart (a new pod, a crash, an OOM kill) empties it, setup included, so a postStart hook runs vault/k8s/configure-vault.sh (mounted from a ConfigMap) on every start, before the pod turns ready. It enables the KV v2 mounts services/ (one path per service) and infra/ (reserved), and the kubernetes auth method with a role and a policy per service (stock-app-policy.hcl); the secrets themselves are gone (what survives what). Prometheus scrapes /v1/sys/metrics. How services sign in: Identity & secrets.

monitoring · metrics

Prometheus

At prometheus.localhost. Discovers every Service annotated prometheus.io/scrape: "true" in apps, monitoring, vault, data, docs and envoy-gateway-system and scrapes each pod every 5 seconds (how). Runs with exemplar storage, so latency samples keep their trace IDs. Evaluates the alert rules in alerts.yml (which).

kubectl apply -k monitoring/prometheus/k8s applies an edited prometheus.yml; Prometheus reloads it by itself (why it has no rollout).

monitoring · node metrics

node-exporter

A DaemonSet, one pod per node including the control plane, with the host's network and process table and read-only mounts of /proc, /sys and /. On kind the nodes are containers sharing one kernel, the Docker host's (on macOS the Docker Desktop VM), and /proc describes that whole kernel: all three pods report the same machine, including every other container on it. The Infrastructure Overview dashboard therefore draws it as one Docker host line; per-node use comes from the kubelet (how). On a cloud, where each node is its own VM, each pod would report its own node.

monitoring · dashboards

Grafana

At grafana.localhost (admin / admin). Datasources and dashboards are files in monitoring/grafana/k8s/, one JSON file per dashboard with a fixed uid, listed in its kustomization.yaml (dashboards as code). Memory limit 1Gi: idle, Grafana 13 uses about 350Mi after start and 500Mi after a day, and it was OOM-killed at 512Mi.

monitoring · trace pipeline

OpenTelemetry Collector

The otelcol-k8s distribution as one gateway Deployment: otlp receiver → memory_limiter → k8s_attributes → otlp_http exporter to Tempo (the pipeline, live). It exposes its own metrics on 8888.

monitoring · trace storage

Tempo

A single binary with local storage on an emptyDir, so traces survive a container restart and are lost when the pod is replaced. No HTTPRoute: Grafana is its UI. Search finds a new trace after about 30 seconds, once a block is cut; opening a trace by ID works at once.

docs · this site

documentation

A Go service at docs.localhost that serves these pages and the live data behind them. It reads the Kubernetes API through informers (how) with a read-only ClusterRole that excludes Secrets, and forwards read-only PromQL to Prometheus, the way Grafana's proxy mode does.

Endpoints

  • / and /*.html: the pages, embedded in the binary
  • /api/map: the cluster as JSON, built from the informer caches
  • /api/prometheus/api/v1/query and query_range: forwarded to Prometheus, nothing else
  • /health (ready once the informers have synced) and /metrics

Code

  • internal/topology turns API objects into the map: pure and unit-tested
  • internal/cluster holds the informers; internal/server the HTTP routes and the proxy
  • web/site: one HTML page per topic, shared CSS and JavaScript modules, no build step
  • web/test: unit tests for the JavaScript model, run by Node's own test runner

Change the docs by editing documentation/web/site/: each fact belongs on one page, others link to it. A new page goes into the PAGES list in assets/js/site.js. Outside the cluster go run . uses your kubeconfig and reaches Prometheus through prometheus.localhost. Without any API (GitHub Pages publishes web/site as it is), the pages render assets/snapshot.json; refresh it from a running cluster with the command below.

cd documentation
go test ./... && golangci-lint run
node --test 'web/test/*.test.js'
go run .     # http://localhost:8080, against your current kubeconfig context
curl -s http://docs.localhost/api/map | jq . > web/site/assets/snapshot.json   # refresh the offline snapshot
cluster-wide · applied first

platform

Everything that isn't one component's: the kind cluster config (kind-cluster.yaml), the Gateway API controller (envoy-gateway/, the upstream release manifest with its CRDs), the shared Gateway, its GatewayClass and EnvoyProxy (gateway/), the namespaces and the RBAC that pods' ServiceAccounts are bound to. If deleting a component should delete a resource, it belongs in that component's k8s/ instead. The EnvoyProxy annotates the proxy's Service, so Prometheus scrapes Envoy's /stats/prometheus on 19001 (job shared-gateway), e.g. envoy_cluster_upstream_rq_xx per route and status class.
